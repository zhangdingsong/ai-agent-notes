
很多人挑大模型或调 API 时，最容易被“窗口、速率、输出上限、价格”绕晕。 其实日常说的“速率”根本不是一个数，而是****三件完全不同的事****。把这三件事拆开，再把主流模型的真实参数摆在一起，谁定上限、谁定账单、谁定速度，一眼就透👇

****一、先分清“速率”的三重含义****

1. ****限额（RPM / TPM）：一分钟最多让你用多少****RPM 管每分钟请求数（并发能力），TPM 管每分钟吞吐 token 总量（Anthropic 还拆成输入 ITPM 和输出 OTPM）。  
    超了就报 429 Too Many Requests——这不是模型变笨，是服务方在闸口拦你。比如 Claude 从 Start 档升到 Scale 档，限额直接翻 10 倍。  
      
    
2. ****生成速度（tok/s）：它打字有多快****人眼阅读约 5–10 tok/s 就够，50 tok/s 已经觉得刷刷出字。  
    这项****不写在合同里****，纯看部署芯片：同一个 Llama 3.3 70B，普通 GPU 云约 80 tok/s，跑在 Groq LPU 上约 1,400 tok/s，跑在 Cerebras 晶圆级芯片上能到 ~2,100 tok/s——速度差出 17–26 倍。  
    另外还有首字延迟（TTFT）：塞 100 万 token 的题，光“读完题”就要等几秒到几十秒。  
      
    
3. ****价格费率（$/1M tokens）：为什么输出比输入贵 3–8 倍****输入是并行“读题”，一口气算完；输出是一个字一个字“写字”，每写一个都要把整个模型和 KV 缓存重读一遍，占用 GPU 时间长得多。  
    小技巧：善用缓存命中（输入通常只要原价 10%）和 Batch 异步任务（通常 5 折），同一模型账单能差 10 倍。  
      
    

****二、谁定天花板？谁定账单？****

记住一句话：****窗口大小找开发商，账单和 429 找服务方。****

- ****开发商****（OpenAI、Anthropic、Google DeepMind、Meta 等）：负责训练模型，定下窗口和能力天花板。
- ****服务方****：负责部署和收钱，定限额、速度和价格。比如 GPT-6.2 Astra 在 Azure 全球区跟 OpenAI 官方同价，但在欧盟/美国区贵 10% 买数据不出境；  
    Claude Sonnet 5.5 在官方、AWS Bedrock、Google Vertex 三家同刊例价，但限额和账单各走各的；  
    Meta 只发开源权重不设公开 API，几十家第三方跑出了几十种价格和速度。  
      
    

在网页版（ChatGPT / Claude.ai）里，这两项全被产品团队定死了；只有调 API 时，你才能在服务方给的上限以内自己填 max_tokens。

****四、为什么窗口在训练时就定死了？****

窗口大小不是产品经理拍脑袋填的，而是四个硬约束算出来的：

1. ****位置编码****：模型靠 RoPE 判断 token 顺序，没见过的位置直接乱码，扩窗口得用 YaRN 等方法“拉伸”并回炉重训。
2. ****注意力算力 O(n2)O(n^2)O(n2)****：长度涨 100 倍，注意力计算量涨 10,000 倍。
3. ****KV 缓存显存****：以 Llama 3.1 70B 为例，128K 上下文单路就要约 40GB 显存（半张 H100）。开到 1M 成本极高，所以服务方不得不收长上下文“过路费”（如超 100K/272K 涨价）。
4. ****中间遗忘（Lost in the Middle）****：塞得进不等于记得住，长文开头和结尾记得牢，中间最容易漏。

****五、最后打破 3 个常见误会****

1. ****窗口 1M ≠ 一次能输出 1M****：窗口是“输入 + 输出 + 历史”共享的总容量。Gemini 4 单次最多写 32K–64K，GPT/Claude 是 128K，DeepSeek V4 给到了 384K。
2. ****RPM/TPM 限额 ≠ 模型能力****：只是服务方的商业闸口，充值升级或换云厂商就能放大。
3. ****标称 1M ≠ 必须全塞满****：越接近上限，中间召回越差、首字等越久、账单越贵。工程上用 RAG 只喂相关片段往往更稳更省。

建议先收藏⭐，下次选型或对账单时翻出来对照，不会再被各种“速率”概念绕晕了。
