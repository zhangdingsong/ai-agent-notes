## 一、开源权重的本质：什么是“开源权重” vs “开源源码”？

很多人刚接触 AI 时，会误以为“开源模型”就是连怎么训练的代码、原始数据集全部大公开。但实际上在 AI 界，绝大多数开源模型（比如 Meta 的 Llama）严格来说只能叫**开源权重（Open-weight）**：

* **公开的是什么（权重）**：就像是一道世界名菜的**最终调料配方和克数比例**（一个几 GB 到几百 GB 的权重文件，里面记录了上百亿甚至上千亿个神经元参数）。
* **不公开的是什么（训练全貌）**：虽然权重公开了，但当初 Meta 用来喂养和训练这个模型的**几万亿字海量原始数据集**、以及当时烧了几个月算力的超级计算机集群架构，通常是**不公开**的。

### 既然权重公开了，大家能拿它干什么？
因为权重文件是公开的，这给开发者和企业带来了巨大的自由度：
1. **私有化部署（自己跑）**：你可以把 Llama 的权重下载到自己公司买的服务器里。这样，你的所有敏感数据都留在自己家里，绝对不会上传到 OpenAI 或 Anthropic 的云端，极具隐私和安全性。
2. **二次微调（Fine-tuning）**：你可以拿这个现成的模型底子，再喂给它你们公司的内部财务数据、医疗病历或特定代码，把它调教成一个行业专属的垂直模型。
3. **摆脱服务商的 429 限制**：在自己手里跑，没有任何人会对你限速（RPM/TPM），也不存在每个月按 token 给你寄账单，上限完全取决于你自己的显卡买得够不够多。

## 二、Meta 的路线演进：从开源 Llama 到旗舰闭源 Muse

Meta 在大模型领域的布局并不是一成不变的，它经历了从“全面开源”到“开源与闭源并行”的战略转向：

1. **Llama 系列（开源权重路线）**：
   * 属于开源权重路线，代码和参数权重公开，任何人都可以免费下载并在本地部署。
   * Meta 曾于 2025 年推出过官方的 Llama API（限时预览版，排队制并联合硬件加速），但在 2026 年 7 月关停了该服务。
   * **Meta 为什么不再自己卖 Llama API？**
     1. 社交和广告才是 Meta 的主业，自建全球机房、维护企业级 SLA、做 24 小时运维太烧钱。
     2. Llama 开源的初衷是借社区生态免费铺开、压低竞争对手，自己卖 API 反而会跟生态伙伴（云厂商）抢生意。
2. **Muse 系列（全新旗舰模型家族）**：
   * 由 Meta Superintelligence Labs 推出的全新旗舰模型线（包含旗舰闭源的 **Muse Spark**、**Muse Wonder**，以及开源版本 **Muse Glimmer**）。
   * 从底层针对**原生多模态、Agent 优先、写代码、调用工具、长程复杂推理**做了深度优化（例如对 KV Cache 显存和思维链长度做了深度压缩）。
   * Meta 将商业化开发者平台重心押在了 Muse 上，推出了官方平台 **Meta Model API**（`api.meta.ai/v1`），直接面向开发者提供商业化调用。
3. **目前谁在跑 Meta 的模型？**
   * **旗舰闭源 Muse**：主要由 Meta 官方运行，企业渠道接入了 Oracle Cloud 及 OpenRouter 等聚合路由平台。
   * **开源版本（Llama 全系列及 Muse Glimmer 等）**：主流云厂商（AWS Bedrock、Azure、Google Vertex AI）和高速推理专厂（Together AI、Groq、Cerebras、Databricks）都在跑，开发者也可以用 Ollama 或 vLLM 在本地私有部署。

## 三、原材料与成品：API 与产品的深层关系

大模型生态可以完美映射为**“汽车制造”**的逻辑：

* **大模型（Model）**：底层的“发动机”。
* **API（应用程序接口）**：把发动机变成**按量计费的水电接口**。它是供程序员写代码调用的 raw 接口，只管发请求、拿文本、按 token 计费，各种参数（如 `max_tokens`、温度）完全由开发者自由控制。
* **产品（Product）**：比如 ChatGPT 网页版、Claude 官网、或者 Antigravity 等。它们是在底层 API 外面套上了方向盘、座椅和仪表盘的**“整车”**——有精美的聊天界面、历史记录管理、文件上传和工作流封装，面向普通大众开箱即用。

## 四、深度拆解：上限、旋钮 (`max_tokens`) 与速率限制

> **核心对照语句**：
> *“API 和产品里定输出上限和速率上限。调 API 时有个 max_tokens 参数，你可以自己填想让它最多输出多少，但不能超过服务方给你的上限。网页版 ChatGPT、Claude 里这个数就是产品定死的，用户改不了。”*

这句话精准揭示了程序员（调 API）与普通用户（用网页版）的权限边界，包含两大核心维度：

### 1. 规矩的分类：输出上限 vs 速率上限
* **输出上限（单次分量）**：规定一个人“一口气最多说多少个字”。模型单次吐字的上限到了就必须停笔，哪怕话没说完。
* **速率上限（次数与用量闸口）**：规定“多长时间内能用多少次”（例如 API 里的 RPM/TPM 限额，或产品里限制“每 3 小时发送多少条消息”），用来防止少数人瞬间把服务器挤爆。一旦超限，就会触发 **`429 Too Many Requests`** 错误。

### 2. 为什么 API 能自己调，网页版却被“焊死”？
* **用 API 时（像“点菜时自己定分量”）**：
  程序员发请求时，可以在代码里自由调节参数 `max_tokens`。
  * **往小了填可以**：如果你怕模型啰嗦、想省钱，可以把 `max_tokens` 设成 100，它写满 100 个 token 就会自动收手。
  * **超过天花板不行**：服务方在后台给这个模型划定了物理上限（比如单次最多 16,384 token）。如果你在代码里丧心病狂地填了 100,000，API 会直接报错拒绝你。**服务方给的上限就是这枚旋钮能拧到的绝对极限。**
* **用网页版 ChatGPT / Claude 时（像“吃餐厅定好的套餐”）**：
  普通用户打开网页聊天，界面上根本没有任何可以调节 `max_tokens` 的输入框。**因为产品团队已经在后台代码里把这个数字彻底定死（焊死）了。**
  * 所以当你在网页版让 AI 写长文写到一半突然停下，并出现一个**“继续生成（Continue）”**按钮时，原因正是它撞到了产品定死的 `max_tokens` 上限，而作为普通用户的你无法手动把它调大，只能点击继续让它发下一次请求接下去写。
